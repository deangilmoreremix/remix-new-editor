## What was built

All four features are GL effects in the existing registry (`src/openchatcut/gl/fx`), so inspector sliders, per-property keys, project persistence (`Clip.fx[].props`) and the Remotion export (`ClipFx.tsx` resolves `ALL_FX` by id) work through the path Stage 3 / 5 used. Array data (mask path, curve points) lives in `Clip.fx[].props`; animated values use `Clip.anim` keys `fx:<index>:<prop>`.

| # | Feature | Effect id | How it works |
|---|---|---|---|
| 1 | Pen-path mask | `builtin:fx-path-mask` (new) | Closed bezier path (`path` = 6 numbers per vertex: anchor, in / out handle offsets; max 16 vertices), flattened on the CPU to <= 128 edges, signed distance + non-zero winding in GLSL. Props: feather, expand, mask opacity, invert, offset X/Y, scale, rotate (mask transform about the path centroid, aspect-correct). Fewer than 3 points = no mask. Preview editing: pen tool (click adds a point, click-drag pulls bezier handles), drag anchors, drag in/out handles (Alt = break the mirror), click the outline to insert a point, double-press an anchor to smooth / sharpen, Delete / button removes a point, Ellipse / Rectangle / Clear buttons. **Animated geometry**: "Key points" keys every anchor at the playhead (`fx:<i>:v<k>x` / `v<k>y` in `Clip.anim`, with the Stage 2 easing / dopesheet); moving an animated anchor (or any anchor while auto-key is on) writes a key at the playhead; the mask transform and feather / expand / opacity are ordinary keyframeable sliders. Handles are static (not animated). Structural edits (add / delete point) bake the animated anchors to the values at the playhead first, because indices change. |
| 2 | Corner pin | `builtin:fx-corner-pin` (new) | 8 number props (`tlx..bly`, frame coordinates, y down, may leave the frame). The CPU builds the inverse homography (`s9/homography.ts`), the shader applies it with a 1-pixel soft edge; outside the quad is transparent; a non-convex / degenerate quad outputs nothing. Four draggable corner handles on the preview (and drag inside the quad to move all four), Reset, "Key corners". Keyframeable through the normal sliders, "Key corners" and auto-key. |
| 3 | Curves editor | `builtin:fx-curves` (id kept) | Draggable RGB + R + G + B curves (click adds a point, drag moves, double-press / Alt-click removes, Reset per channel), Fritsch-Carlson monotone spline (adapted from FreeCut `curve-spline.ts`, MIT, attribution in the file header and `s35/THIRD_PARTY_NOTICE.md`), evaluated on the CPU into a 128-entry per-channel LUT passed as `uniform vec4 u_lut[128]`. Stored as `curve_m / curve_r / curve_g / curve_b` = flat `[x0, y0, x1, y1, ...]`. The five sliders are no longer shown. **Backward compatible**: a project with only the old `p0..p4`, `r_mid`, `g_mid`, `b_mid` props has no `curve_*` keys and is rendered by a CPU port of the old Catmull-Rom curve (same maths; sampled through the LUT, GPU vs CPU reference diff 0 in the browser check); the editor starts from its five master points; the first edit writes all four `curve_*` curves and the legacy props are ignored from then on. An untouched effect starts as a plain line. |
| 4 | Colour picker | inspector | Every `kind: 'color'` prop now gets a native colour input (it showed nothing before: colour wheels, duotone, chroma key colour, ASCII, light leak, etc.). New: `FxDef.colorPicks` over HSV slider triples - Gradient Map has a swatch per stop that writes the three HSV sliders (so stops stay keyframeable and old projects are unchanged). Night Vision got a real `tint` colour prop (default = the old hard-coded green). Colour props themselves are not keyframeable (the keyframe engine is scalar); the HSV stops are. |

## A bug the real export check found and fixed (pre-existing, in `ClipFx.tsx`)

While exporting, the animated mask only ever grew. Cause: while rendering, `ClipFx` copies the GL frame into a 2D "mirror" canvas with `drawImage` (source-over) and never cleared it, so opaque pixels from earlier frames stayed. Any effect whose transparent area changes over time (animated masks, a keyed corner pin, luma key on moving content) was wrong in exports. Fix: `clearRect` before `drawImage` (3 lines, `[remix]` comment). Regression test reads the source order; the real export now matches (below).

## Limits (stated plainly)

- Only the path-mask geometry (anchors) and corner values were checked in a real export; the mask transform keys, feather / expand / opacity keys, invert, bezier-handled paths and the Night Vision tint were checked in the preview and at shader level, not as exported frames.
- The preview handle overlay is preview-only UI. It is positioned with the clip's CSS transform (pose) but ignores `clipPath` crop and the follow-subject zoom wrapper is only inherited by position; the handles at the frame edge are half hidden by the stage's `overflow: hidden` (grab the inner half).
- A corner-pin quad that becomes non-convex while dragging shows nothing until it is convex again (by design: the warp of a bow-tie is not a picture).
- Anchors are animatable, bezier handles are not. Colour props are static (no keyframes). Mask path size is capped at 16 points x 8 flatten steps (128 edges, one `vec4` each, i.e. 128 uniform vectors; WebGL2 guarantees 224). The CPU twin of the mask shader uses a fixed minimum feather; the shader also enforces about 1.5 px of edge anti-aliasing, so extremely small feathers differ by under a pixel.
- Pen drags do not close the path explicitly: a path with 3+ points is always closed. No open paths / multiple subpaths; use several Path Mask effects (their alphas multiply), no mask "add / subtract" modes.
- The test clip is made of saturated primary colours, so tone-curve checks in the browser use the black point and the red end point (a mid-tone lift is invisible on 0 / 255 values); the maths for mid-tones is covered by the vitest and the GPU-vs-CPU comparison.
- The export check used Chromium's H.264 encoder (the sandbox build has one); real hardware encoders were not tried. Under load the smoke retries pixel checks (SwiftShader and the preview video pool are slow); no assertion was relaxed to pass.
- Not touched / not verified: Electron native visual path, Supabase-backed project tables (the web store is JSON in IndexedDB, read back here).
