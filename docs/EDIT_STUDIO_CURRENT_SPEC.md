| Watermark Scale | `<input type="number">` | 0.1-1, step 0.1 | 0.2 |

#### Dynamic Controls (model-specific)
- Generated by `buildDynamicControls(modelId)`
- Reads `model.inputs` from `getI2IModelById()`
- Skips `prompt` field
- For `enum` → `<select>`
- For `int`/`integer` → `<select>` with min-to-max iteration (CRUDE)
- For everything else → `<select>` with single default value (CRUDE)

## Current Gaps (vs Historical Ideal)

1. **Dynamic control UX is crude**: All dynamic controls are `<select>` elements, even for numeric ranges that should use `<input type="number">` or sliders, and boolean values that should use checkboxes.

2. **No input validation**: Static controls have min/max attributes but no runtime validation. Dynamic controls have no validation at all.

3. **Error handling is primitive**: Uses `alert()` for all errors.

4. **Loading state is minimal**: Button text changes to "Processing..." with a spinner character.

5. **Model selector visibility**: Only shown for `seedream-5.0-edit` tool. Other tools with `hasPrompt: true` in their model definition (like `ai-product-shot`) don't show the model selector.

6. **No support for image/image-array inputs**: Dynamic control system doesn't handle `image` or `image array` field types.
