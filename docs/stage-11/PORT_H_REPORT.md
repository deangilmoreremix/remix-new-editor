# Port H: pitch shift and time stretch (CineGen, `#/timeline`)

## What was built
Per-clip pitch shift in semitones (-12 to +12) and cents (-100 to +100), plus a "Preserve pitch when speed changes" option that also covers the Stage 1 speed-ramp presets.

- **Access path:** Edit tab > **Media tools** (bottom right) > **Audio** tab > section **Pitch** for the selected clip (a selected video clip edits its linked audio-track clip, like the EQ). Controls: Semitones slider, Cents slider, "Preserve pitch when speed changes" checkbox, **Reset pitch**, and **Apply to N other pieces** (copies the pitch to the other clips cut from the same audio on the track, because a speed ramp cuts a clip into pieces; setting the pitch before the ramp also copies it to every piece). Mouse only, no keyboard shortcuts. Hover help for both sliders (`help-content.ts`, `help-coverage` test passes).
- **Preview:** an AudioWorklet (`lib/audio/pitch-worklet.processor.js`, SoundTouch) inserted between the media element source and the EQ chain: source -> pitch worklet -> EQ -> clip gain -> master. "Preserve pitch" uses the element's own `preservesPitch` (default true; off = tape mode where pitch follows speed). Latency of the shifted clip is about 0.1 s (push-based processing; not compensated).
- **Fallback:** without AudioWorklet (or if the module fails to load) the clip plays unshifted and the Audio tab shows a warning (graph `onPitchWarning`, `pitchAvailable()`); the export still has the shift.
- **Export:** the shifted / stretched sound of the clip's source range is rendered with SoundTouch on the main thread (yielding between chunks, cancellable) into a WAV blob (`lib/audio/pitch-bake.ts`); the export clip then plays that file from 0 at speed 1, so nothing is stretched twice. Order: pitch bake, then EQ bake on the pitched file, then master / track volume as gain in `buildExportState` (the preview order; no double processing). Cached per (source, range, speed, pitch). A failed bake keeps the clip unshifted and adds a warning; an unlinked video clip with a pitch setting is warned as preview-only (same rule as EQ).
- **Important finding (measured in the real export):** the Remotion web renderer plays `playbackRate` as a plain resample, so a 2x clip came out an octave higher, while the preview preserves the pitch. With the new default (preserve pitch) every audio clip with speed != 1 is therefore baked as a time-stretch, which changes (fixes) the sound of existing exports of sped-up clips so they match the preview. Tape mode (preserve off) with no shift is left to the composition's own resample (identical result, verified). A video clip with its own sound and no linked audio is unchanged (no bake, no new warning).
- **Persistence:** `Clip.pitch = { semitones, cents, preservePitch }` (neutral = absent). JSON project path: the field. DB path: `stage4_json` (shared with the EQ, no schema change; old rows load without pitch, bad values are dropped).

## Limits and not done
- Real preview was checked on single clips only (the 2.8 s ramped timeline ended before the measurement); ramp audio was checked in the export, not live.
- Preview pitch is live-processed, so the shifted clip lags the picture by about 0.1 s (not compensated). Shifted audio at speed != 1 relies on the element's `preservesPitch` plus the worklet.
- Pitch is per clip (no keyframed pitch). Bake decodes the whole source (up to 20 minutes, like the EQ), runs SoundTouch on the main thread with yields (a worker is a possible later step), 16-bit WAV output.
- The export now stretches speed-changed audio clips (see finding above): a behaviour change for existing projects with speed != 1 (matches the preview).
- Preview in Safari / Firefox: needs AudioWorklet and `preservesPitch` support; otherwise the warning is shown. Not tested outside Chromium.
- Smoke note: while testing, a broad `pkill -f chrome-linux64/chrome` was used several times and may have closed other sessions' headless browsers.
