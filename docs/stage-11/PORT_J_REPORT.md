### a) Crash recovery (original code; FreeCut has none)
- `lib/recovery/crash-recovery.ts` (pure + IndexedDB via `idb-keyval`, own database `cinegen-recovery`), `components/workspace/use-crash-recovery.tsx` (hook and prompt), 3 small additive edits in `workspace-shell.tsx`.
- While a project has edits that the normal 500 ms debounced save has not finished, a snapshot of `timelines`, `activeTimelineId` and `assets` is written (150 ms debounce, best effort again on `pagehide`). A successful save removes it, but only when the saved state is the live state (a newer edit keeps its snapshot). If the page dies first, or the save fails, the snapshot survives.
- On open, a snapshot that equals the loaded project (key-order independent, blob URLs ignored) is dropped silently; a different one opens the prompt. **Recover** dispatches ordinary, undoable workspace actions (`SET_TIMELINE`, `ADD_TIMELINE`, `ADD_ASSET`, `UPDATE_ASSET`, `SET_ACTIVE_TIMELINE`) after running the load migrations from the snapshot's schema version, so the normal save then persists it; **Discard** deletes it. Nothing is ever deleted from the loaded project.
- Versioned and defensive: envelope `v: 1`, project id, `schema` (a snapshot from a newer project schema is ignored), age limit 14 days, 24 MB size cap, shape validation, plain-data round trip; storage errors never throw.
- Tests (`src/cinegen/__tests__/stage11/crash-recovery.test.ts`, real timeline operations): write / read / clear, plain data, rejection of wrong project / version / newer schema / stale / malformed (and deletion of unusable entries), storage failure, recovery plan for an edit, a new timeline, a new asset, a restored blob URL.
- Browser (`docs/stage-11/smoke/recovery-smoke.cjs`, log `results/recovery-smoke.log`, ALL PASS, real `#/timeline`, real imported mp4): place a clip and let it save; make an edit (a 16-piece speed ramp) while the page's IndexedDB writes to the project store throw (simulated failing save); the snapshot exists, the saved project still has the old state; `page.close({ runBeforeUnload: false })`; reopen the project: the prompt shows (16 clips in 1 timeline); before Recover the editor shows the saved state (2 cards), after Recover 16 cards, the recovered state is saved (16 clips in the store) and the snapshot is gone; a reload after a normal save shows no prompt; a second unclean exit shows the prompt again and Discard keeps the saved project.
- Limits: the snapshot covers timelines, active timeline and assets only. Overlay-lane items, workflow nodes, spaces, director, elements and exports are not recovered. A recovered asset that does not exist in the saved project keeps its old `blob:` URL (the Fix B local-media restore runs on project load, not on recover). The "kill" in the smoke is a closed page plus a forced save failure, not an operating-system kill of the browser process.

### b) Speed-ramp curve
- `lib/editor/stage11/speed-curve.ts` (pure), `components/edit/speed-curve-editor.tsx`, a one-option extension of `applySpeedRamp` (`speeds`), one button and popover wired in `use-stage1-editing.tsx`.
- Model: points over the clip's source range (position 0..1, speed 0.1x to 8x) with a per-segment `EaseSpec` (presets, cubic-bezier, spring), the same easing model and `applyEase` as the Stage 2 keyframes. The segment easing is edited with the existing Stage 2 `CurveEditor` component ("Segment curve..."). The graph has draggable points, double-click to add / remove, a pieces slider (4 to 64), preset curves and a live "10.00 s of source plays in 4.36 s" line.
- Time remap: time to play source fraction u is `S * integral_0^u dx / speed(x)` (fixed composite Simpson rule, no clock, no random). Preview and export both play one constant speed per clip, so the curve is realised as N consecutive clips over equal source spans whose speed is the harmonic mean of the curve over the span. Every piece boundary then lies exactly on the remap (source position and timeline time) and the total duration equals the exact integral; only the motion inside one piece is constant-speed. Linked audio is ramped identically, later clips ripple, undo restores the original.
- Tests (`speed-curve.test.ts`, 10): closed-form check (linear 1x to 4x has duration `S * ln 4 / 3`), inverse remap, easing effects (ease-in-out, custom bezier), clamping with a spring that overshoots, determinism with `Date.now` and `Math.random` trapped, harmonic-mean durations equal the exact remap for all presets, untrusted input, and the real `createDefaultTimeline` / `addClipToTrack` / `exportClipsFromTimeline`: piece boundaries equal `curveTimeAt` at every piece start, contiguous source coverage, ripple of a following clip, linked audio, per-piece export speeds.
- Browser export (`export-smoke.cjs`, `speedcurve-analyze.py`, `results/speed-curve-export.log`, `results/speed-curve-analysis.json`): 10 s source clip whose picture encodes its own time (luma ramp); curve "Flash forward" with the first segment edited in the real bezier editor and the middle point dragged, 16 pieces (speeds 1.01 to 7.60), real Export tab, Draft 720p 30 fps, H.264 mp4. ffprobe duration 4.373 s against 4.364 s on the timeline. Each exported frame's source time was read back from its luma, calibrated against the same clip exported plain through the same renderer, and compared with the piece list: over 111 frames in the calibrated range, mean |error| 0.030 s, p95 0.093 s, max 0.173 s (one output frame at 7.6x is 0.25 s of source). The measured local speed in the file runs from 0.0 (end of clip) to 8.17x, following the curve.
- Honest notes: a first run used the source file itself as the calibration and reported a larger error (mean 0.165 s, `results/containers-run-1.log`); that was a calibration artefact (limited-range clipping at both ends of the luma ramp and a different colour path), not an export fault, which the plain-export calibration shows. A run with 40 pieces made Chromium crash in this shared, memory-limited machine; I did not diagnose it and used 16 pieces for the export evidence. Preview playback of many pieces (seams at the piece boundaries) was not observed. Limits: the curve is not stored, so a ramped clip cannot be re-opened in the editor (undo, or draw a new curve over a piece); audio pitch changes with speed as in Stage 1.

### c) Audio-only export, MOV / MKV / WebM
- Verified first that the installed `@remotion/web-renderer` (4.0.540) already writes `mp4 / mov / mkv / webm` video and `wav / mp3 / aac / flac / ogg` audio-only files (`WebRendererContainer`, its MP3 / AAC / FLAC encoders are bundled dependencies). Export QA (a video check) is skipped for audio-only files.
- Tests (`containers.test.ts`, 4): every listed container is known to the installed renderer with matching audio-only flag and video codecs (mp4 / mov / mkv accept H.264, webm VP9), capability gating logic, lookups, and the runner's accepted list equals the picker's list.

### d) Lottie completions
- FreeCut's only Lottie editing beyond Stage 2 is value slots (scalar / 2D, `S/infrastructure/lottie/lottie-slots.ts`). Discovery is adapted into `lib/editor/stage11/lottie-extra.ts` (attribution header with repo, path, commit, MIT); one fix over upstream: an animated slot whose keyframe start value is a one-element array is recognised. FreeCut applies slot values through dotlottie-web's native setters; the editor's players (lottie-web preview, `@remotion/lottie` export) have no slot API, so the value is baked into every property that references the slot (`sid`) and into the slot table. Layer visibility (the standard Lottie `hd` flag) has no FreeCut counterpart and is original code.
- Wired through the one shared patcher (`applyLottieEdits`, 3 additive lines) and the two existing call sites (`overlayRender.js`, `TimelineComposition.jsx`, one line each); saved in the sticker overlay options as `lottieValues` / `lottieHidden`; UI in `lottie-edit-section.tsx` (value inputs, a collapsible layer list with show / hide).
- Tests (`lottie-extra.test.ts`, 6): slot discovery, baking (3D position keeps z, animated slot becomes static, table updated, input never mutated), invalid slots ignored, layer list and hiding, the combined patcher. Browser (`lottie-check.cjs`, `results/lottie-check.json`, ALL PASS): bundles the real `lottie-web` with the patcher and renders in Chromium: hiding a layer removes its path from the SVG, a value slot of 35 yields `opacity="0.35"`, a position slot moves the layer's transform.
- Limits: an animated slot becomes static; only top-level layers; the sticker panel UI was not driven in a browser and the edited Lottie was not rendered through `@remotion/lottie` in a real export (same patched JSON, but not run). Most public Lotties have no `slots` table, so the layer list is the more broadly useful part.

### e) Lift / Extract the in-out range
- `lib/editor/stage11/range-edit.ts` (pure), two buttons in the existing range controls. FreeCut's range removal (`stores/actions/edit/range-removal-actions.ts`) is wired to its stores, so only the idea is used (no code): clips are cut at both edges with the editor's `splitClip`, clips inside are removed, and Extract moves later clips on unlocked tracks earlier by the range length. Locked tracks are not touched; markers inside the range are removed and later ones shift; a dissolve whose clip was removed is dropped, and the outgoing side of a dissolve follows the piece that still ends at it (`splitClip` leaves it on the first half).
- Tests (`range-edit.test.ts`, 7), browser (`range-smoke.cjs`, `results/range-smoke.log`, ALL PASS): range 2 s to 4 s of a 6 s clip, Lift gives pieces 0-2 and 4-6 with a "Lifted 2.00 s" notice, undo restores the clip, Extract gives 0-2 and then the source from 4 s with the gap closed and the range cleared.
- Notes: undo needed **two** Ctrl+Z presses in the browser run (Stage 1 reported the same quirk for Insert; cause not isolated, not investigated here). Overlay-lane items and captions are not moved (same limit as Insert / Overwrite).

## Judged incompatible, and why (details in the parity file)
- **Freeze frame**: needs a captured still (new image asset) or a freeze mode in `PlaybackEngine` and `TimelineComposition`; speed 0 is not supported. Not done.
- **dotLottie archives / themes / WASM player, LottieFiles browser**: a second Lottie runtime next to lottie-web and `@remotion/lottie`, plus an external API.
- **WGSL effects, transitions, scopes, GPU compositor, glyph-atlas text**: WebGPU-only and bound to FreeCut's pipeline; the product runs on WebGL2.
- **Workspace file system, OPFS storage, service worker / PWA, COOP + COEP headers, headless / agent API, hotkey registry**: FreeCut's own application architecture; COOP / COEP would break cross-origin embeds the product relies on.
- **Mixdown / ducking / render queue internals** (`S/runtime/renderer/**`): FreeCut's renderer; export audio comes from the Remotion composition.
