## 1. GL transition window honours blend mode, background fill, captions and the lower tracks

**Cause.** The window was an opaque layer (over the background colour) drawn on top of every layer, with the raw clips still drawn underneath.
**Change.**
- Export: `GlTransitionLayer` now outputs a **translucent, premultiplied** picture (no background colour). `createGlRuntime(canvas, { premultiplied })` is a new optional flag (context `premultipliedAlpha`, texture upload premultiplied); default behaviour of every other runtime is unchanged. Each side keeps its own alpha (clip/keyframe opacity, fade, crop, letterbox), the shader mixes premultiplied pictures, so opacity < 1 fades towards what is below.
- `TimelineComposition`: the window is drawn **at the incoming clip's z position** (`GlWindow`), with `mix-blend-mode` of the more visible side (outgoing for progress < 0.5, incoming after); both clips' own layers are not drawn inside the window (`GlHidden`). Captions (separate layer) and clips on higher tracks are therefore visible in the window. Specs without looks (old models) keep the old top-layer path.
- Background fill (`transform.fill`) is drawn per side first (`styledFrame.ts` `fill`), moved only by the keyframe transform/opacity, as in the clip layer. `attachGlSideLooks` now also records `outLayerId`/`innLayerId`; `glSideLayerFrom` carries `clipBlend`.
- **Found and fixed on the way:** in the normal clip layer the blend wrapper sat *inside* the opacity wrapper (an isolated CSS group), so blend mode + opacity < 1 never blended with the layers below in the export. The blend is now the outer element. A first window frame was captured blank (the raw layers are gone): the frame hold is now taken in a layout effect and released two animation frames after the draw (reproduced ~1 in 5 renders before, 6/6 correct after).
- Preview (`gl-clip-layer.tsx`): the window has its own premultiplied canvas (`gl-transition-layer`), z-index of the incoming video, blend mode, no black background, the engine's blurred fill canvases are hidden and drawn into the sides (`data-fill-for` on them), `timeline-viewer.tsx` shows the captions of both clips inside the window. The playback engine now also sets `mix-blend-mode` on the `<video>` (it only did so for clips with effects before).

**Evidence (real export, `docs/stage-10/smoke/fixe-export-smoke.cjs`, log `docs/stage-10/evidence/fixe-export-smoke.log`).** L on V1, A -> B on V2 (blend `screen`, opacity 0.6), 1 s GL cross-dissolve at 2-3 s (frames 60-89), caption on A at 2.2-2.9 s. Expected pixel = 0.4*L + 0.6*screen(L, mix(A,B,smoothstep(u))) from the decoded source colours; frames before / at the start of / inside / at the end of / after the window: max error 5.4 levels, largest excess frame-to-frame step 0.0 (f59 -> f60 and f89 -> f90). Caption: 1250 white pixels in the lower half inside the window vs 0 before it. A model without looks (raw frames on top, the old path) misses the expected value by 84 levels inside the window. 3 assertions + 1 contrast assertion pass.
Preview (`fixe-preview-smoke.cjs`, `?mode=win`): real `GlClipLayer` over real `<video>`s with the engine's style strings, real `activeGlTransition`: max error 5 levels at t = 1.5, 1.99, 2.01, 2.3, 2.5, 2.8, 2.99, 3.01, 3.5; no jump at the window edges. This harness does **not** run `PlaybackEngine` or the full editor UI.
Unit tests: `fixe-gl-window.test.ts` (3).

## 2. Compound clips render as ONE group

**Change.** `flattenCompounds(tl)` now keeps the compound's look off its children: picture children get `compoundGroup`, the compound itself (without `compound`) is returned in `Timeline.groups` (runtime only, never saved). Group = the compound's own fx, LUT, opacity (static, keys, anim), blend, transform/anim, crop, fades, zoom, flip, applied once. (Crop, fades, zoom and flip of a compound were not applied before.)
- Export: `exportClipsFromTimeline` appends each group as a picture-only item (`type: 'group'`, volume 0) at the end; `timelineToComposition` makes a `group` layer at the compound's track position holding its children; `GroupLayer` draws each child (own look, fx, blend, fill) into one offscreen canvas in z order, then runs the compound's fx once and its transform/crop/zoom/flip/opacity once (same `resolveSideLook` as a clip).
- Preview: `gl-group-layer.tsx` does the same over the engine's `<video>` elements (children and their fill canvases hidden while the group shows), with the compound's transform/crop/opacity/blend as CSS on the group canvas. Wired through `edit-tab.tsx` -> `timeline-viewer.tsx`.
- Kept per-child ("bake", old behaviour, `applyGroupLook`): `expandCompound`, `flattenCompounds(tl, { bake: true })` (used when an export range is set, because the group's time base cannot be cut), a compound that contains a compound (the outer look is baked onto the inner compound, which then renders as a group), a compound containing GL transitions. Nest/expand, save/load rows and Stage 2 anim on compounds: unit-tested below; the existing 13 `fixa-compound-look` tests now run in bake mode.

**Evidence (real export).** A (V1 0-4) and B (V2 2-6, on top) overlap 2-4 s, compound opacity 0.5, black background: t = 1 s `108,29,20` (0.5*A), t = 5 s `13,33,115` (0.5*B), overlap t = 3 s group render `13,33,115` = 0.5*B (one 50 % layer), per-child bake `65,46,123` = 0.5*B + 0.25*A (expected 64,40,120); difference 52 levels. 3 assertions pass. Preview harness (`?mode=grp`, real `GlGroupLayer`): `12,33,114` in the overlap = 0.5*B. Unit tests: `fixe-compound-group.test.ts` (5).

## 3. Legacy transition layout migration (project schema version 2)

`src/cinegen/lib/editor/project-migrations.ts`: `PROJECT_SCHEMA_VERSION = 2`. On load, a project without `projectSchemaVersion` (or < 2) has each dissolve/GL transition checked: B overlaps A by `o`, and (a) the clip after B on its track starts exactly `o` after B's end -> it and everything after it (plus the audio in sync with each) move left by `o`; (b) B's linked clip is exactly `o` later than B -> it moves by `o`. Nothing else is touched, so a timeline already in the new layout returns the very same object, and an unrecognisable layout is left alone. The version is saved (`projectSchemaVersion` at the top of the JSON snapshot and inside `workflow` for SQLite; the web store keeps it through `createLegacySnapshot`), so it never re-applies. Wired in `workspace-shell.tsx` at the SQLite load, JSON load and cloud-refresh paths. It is applied automatically on load (no prompt/notification UI was added).
Tests `fixe-project-migration.test.ts` (6): legacy fixture with linked audio equals what the current `addTransition` produces from the same edit (positions, duration, C's audio); new layout untouched (`toBe`); idempotent and stamped projects never inspected; an inconsistent legacy chain is not guessed; save -> load -> save byte-stable (stamped and unstamped); a plain gap that is not the overlap stays.
