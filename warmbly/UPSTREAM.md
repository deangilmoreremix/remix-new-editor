Modifications for this repo (theme only, via Warmbly's own accent mechanism):
- `web/src/styles/theme-brand.css` (new): accent scale generated by upstream `accentScale()`, plus dark surfaces.
- `web/src/global.css`: imports theme-brand.css. `web/index.html`: `data-accent`, dark by default, surface color.
- `web/src/lib/theme.ts`: only the dark browser-chrome color. Dark is the default through Warmbly's own `setDefaultTheme("dark", true)` call in `web/src/main.tsx` (upstream's `DEFAULT_THEME` and its tests are untouched).
- Removed the marketing/landing site (`site/`), except `site/public/{install.sh,cli.sh,cli.ps1}` and their `.sha256` files, which Makefile targets use. Removed the `make site` target. Everything else is unmodified upstream.
- No Warmbly sign-in. `web/src/lib/hostSession.ts` (new) loads the host app's Clerk session (`VITE_CLERK_PUBLISHABLE_KEY`, optional `VITE_HOST_SIGN_IN_URL`, default `/sign-in`) before the dashboard renders and stores the Clerk JWT as the dashboard's Token; a signed-out visitor is sent to the host's own sign-in. `refreshToken` asks Clerk instead of calling `/auth/refresh`. The login, register, reset-password, SSO pages and their hooks are deleted; `/auth`, `/auth/login`, `/auth/register` and `/auth/*` are redirect-only routes to the host sign-in. Onboarding (workspace setup after sign-in) is kept. Adds `@clerk/clerk-js` to `web/package.json`.
- The Warmbly backend is not wired yet: it must accept the Clerk JWT as its bearer token (or exchange it), and `VITE_API_URL` must point at it.
- Warmbly Studio (standalone studio, like Website Builder): `warmbly/web` builds to `public/warmbly-app/` via `npm run build:warmbly` (`vite build --base=/warmbly-app/`, also part of `npm run build`), is shown by `src/components/WarmblyStudio.js` in an iframe, routed as `#/warmbly` (`src/lib/router.js`), listed in the Agents group of the side menu and `STUDIO_ROUTES` (`src/lib/studioRoutes.js`), with Netlify SPA fallbacks for `/warmbly-app/*`. It shares the host's Clerk session (same origin). `warmbly/**` is excluded from the root vitest run. Web app changes for this: `router.tsx` basepath from `BASE_URL`, `vite.config.ts` font preload and `faviconBadge.ts` respect the base, `hostSession.ts` sends the whole host page to `/signin`. Served from the host's own origin in dev too (Warmbly's dev server forbids framing): run `npm run build:warmbly` first; `VITE_WARMBLY_URL` overrides the address.
- Known gap: the "Ask SmartVideo" knowledge base has no guide for `warmbly` yet (`src/data/askKb/`), so `askSmartVideo.test.js` "has a guide for every side-menu studio" lists it, as it already did for `zackd` and `video-pages`.
- Feature guides (the docs site, like docs.warmbly.com): `warmbly/docs` (Fumadocs, static export) builds to `public/warmbly-docs/` with ``npm run build:warmbly-docs`` and is served from `/warmbly-docs/` (Netlify rule for `/warmbly-docs`; the build runs as part of the repo build and retries once). The studio's in-app links to `https://docs.warmbly.com/...` point at it through `VITE_DOCS_URL=/warmbly-docs` (`docsLinks` plugin in `web/vite.config.ts`). Docs changes, all env-driven (defaults are upstream's): `next.config.mjs` basePath from `DOCS_BASE_PATH`; `components/shared/provider.tsx` search index URL; `DOCS_SITE_URL` for `metadataBase`, sitemap and robots (set it in the deploy env for canonical URLs); `app/global.css` brand block. Guide screenshots are Warmbly's own images and keep its original colors.
- Docs are how-to guides only (no upgrade material): removed the `learn/`, `api/` and `development/` sections and the guides `warmbly-cloud`, `billing`, `partnership` and `ai-credits` from `warmbly/docs/content/docs/`, and in the other guides the lines, list items, table rows and sections about plans, trials, billing, allowances and Warmbly Cloud (a one-off scripted cleanup, so after updating upstream the same cleanup has to be repeated). Docs app: removed the section switcher and the header links to warmbly.com, app.warmbly.com and GitHub; the 404 page lists only Guides. The build sets `DOCS_SITE_URL` from the deploy's `URL`. The studio's in-app links to removed pages go to the guides home (`docsLinks` in `web/vite.config.ts`). The generated help guide (`scripts/build-warmbly-guide.mjs`) therefore has 52 features, with no cloud or billing wording.
